# Windows 이식 검증 기록

2026-09-19, Windows 11 Pro build 26200에서 검증했다.

## 통과

- 공통 코어를 Linux에서 빌드하고 기존 코어·마이크 상태·신규 스트리밍 테스트 3개를 실행했다.
- Windows x64 EXE/DLL을 빌드하고 **Windows에서 직접 실행한 CTest 4/4가 통과**했다: 코어, 마이크 상태, 스트리밍, APO 계약 테스트.
- 기존 AEC 감소량/음성 보존 회귀 기준은 낮추지 않았다.
- Windows APO 테스트는 실제 패키지 DLL의 로딩·COM 생성/해제, 형식 협상, EQ 결과, 1024프레임 지연, 입력 1 선택, Unicode 파일 교체, 효과 상태 이벤트를 포함한다. 장치 등록은 하지 않는다.
- 설치 복원 테스트는 임시 HKCU 키에서 문자열, 다중 문자열, DWORD, 새 키 제거, 직렬화 후 복원 및 재실행을 검증했다.
- Fluent 디자인 변경 전 네이티브 설정 창의 생성, 응답 및 정상 종료를 확인했다.
- `git diff --check` 통과.

## 빌드 환경

이 PC에는 MSVC/Windows SDK가 설치되어 있지 않아 임시 MinGW-w64 도구체인과 Microsoft 공개 Windows SDK 인터페이스 헤더로 크로스 빌드했다. 테스트 EXE는 Linux 에뮬레이션이 아닌 실제 Windows에서 실행했다. 임시 도구체인/SDK 헤더는 리포지토리에 포함하지 않았다.

MSVC x64용 CMake/PowerShell 빌드와 GitHub Actions 워크플로를 추가했지만, 이 세션에서는 MSVC 및 원격 CI 실행을 검증하지 않았다. macOS 실행 검증도 하지 않았다.

## 합성 신호 성능

- 타임스탬프와 480프레임 패킷을 사용하는 스트리밍 테스트: 약 **40.9dB** 반향 감소.
- 기존 Windows AEC 벤치마크: 단일 코어 환산 **2.319%**, p99 **470.2μs**, 선형 감소 29.183dB. 이 CPU 결과는 벤치마크에 표시된 기존 1.5% 목표보다 높다.
- 마이크 스트리밍 계층의 고정 추가 지연: **21.33ms**. EQ에는 추가 버퍼 지연이 없다.

실제 스피커/방/마이크 측정값이 아니며, 드라이버 지연·오디오 스케줄링 지연은 별도다.

## 미완료: 실제 오디오 장치 적용

SMSL USB DAC 및 MOTU In 1-2 endpoint가 존재하는 것을 확인했지만 설치 사전 점검에서 `SoundControlAPO.dll`의 서명이 `NotSigned`로 확인되어 설치가 중단되었다.

- 장치 효과 레지스트리 및 Windows 오디오 보안 설정은 변경하지 않았다.
- 실제 audiodg 로딩, 스피커 EQ 측정, 실제 마이크 반향 감소, 통화 앱 호환성, 실장치 재연결은 아직 검증하지 않았다.
- 다음 검증에는 Protected Audio의 요구 조건을 충족하는 서명된 APO가 필요하다. 일반 프로세스에서 DLL 로딩 테스트가 통과한 사실은 audiodg의 수용을 보장하지 않는다.

## Fluent UI 변경 후 검증 범위

새 UI의 Windows x64 빌드는 통과했다. 밝게/어둡게 테마, 고대비 색상, DPI 재배치, 작은 창의 스크롤, 네이티브 입력 컨트롤을 구현했다. Windows 자동화 도구가 WSL 작업 경로를 거부하여 실제 창 캡처와 클릭 검증을 진행하지 못했다 (`sandboxCwd is not a local file URI`). 따라서 한글 렌더링, 각 배율의 시각적 완성도, 키보드/스크린 리더 접근성 검증은 완료로 표시하지 않는다.
